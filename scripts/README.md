# Скрипты

Всё, что приходится делать с рамкой руками: собрать, поставить, посмотреть журналы,
разобраться с падением. Написаны для Git Bash — он и так стоит вместе с Git, а Windows
PowerShell для этих задач неудобен. Запускать из этого каталога:

```bash
cd scripts
./deploy.sh
```

## Что где

| Скрипт | Зачем |
|---|---|
| `devices.sh` | Какие рамки подключены и что на них стоит |
| `build.sh` | Собрать APK (Release). `--tests` — сперва прогнать тесты |
| `test.sh` | Тесты `PhotoFrame.Core`. Можно с фильтром: `./test.sh Immich` |
| `deploy.sh` | Собрать, поставить, запустить. `--no-build` — поставить готовое |
| `run.sh` | Перезапустить приложение на рамке |
| `logs.sh` | Журнал приложения. `--dump`, `--warn`, `--all` |
| `crash.sh` | Всё после падения: исключение, сигнал, жалобы декодера, пульс |
| `heartbeat.sh` | Журнал состояния: `20`, `100`, `08:0`, `--pull` |
| `screenshot.sh` | Снимок экрана. `--series 12` — серия кадров подряд |
| `frame-info.sh` | Состояние рамки одним экраном |
| `fix-time.sh` | Сервер времени, часовой пояс, часы по компьютеру |
| `push-immich-key.sh` | Положить файл с ключом Immich на рамку |
| `common.sh` | Общая часть: adb, выбор рамки, пути. Отдельно не запускается |

## Две рамки

Когда подключена одна, скрипты берут её сами. Когда несколько — придётся сказать, какую,
иначе обновление уехало бы не на ту:

```bash
./devices.sh                    # посмотреть серийные номера
FRAME=N6DO11BXRT ./deploy.sh    # поставить на конкретную
```

## Если рамка не видна

`adb devices` пуст чаще всего не из-за отладки, а из-за железа: у этих рамок попадаются
кабели только для питания, а данные идут лишь через OTG-гнездо. Разветвитель тоже стоит
убрать из цепочки.

Запроса «разрешить отладку?» рамка не показывает вовсе, и подходит ей только тот ключ,
который ей однажды скормили. Скрипты берут его из `ADB_VENDOR_KEYS`, по умолчанию
`C:\tmp\adbkey.txt`; путь можно переопределить:

```bash
ADB_VENDOR_KEYS=/путь/к/adbkey ./devices.sh
```

Если Visual Studio уже поднял свой сервер adb без этого ключа, рамка окажется
`unauthorized` — тогда `adb kill-server` и заново.

## Почему запуск сразу после установки

`deploy.sh` не только ставит APK, но и открывает приложение. Пока приложение ни разу
не открывали, Android держит пакет остановленным и не рассылает ему `BOOT_COMPLETED` —
то есть автозапуск после включения рамки не сработает. Один запуск снимает это
состояние навсегда.

## Что смотреть, когда что-то не так

```bash
./crash.sh                 # падало ли, и с чем
./heartbeat.sh 60          # что рамка делала последний час
./logs.sh --warn           # на что жаловалось приложение
./screenshot.sh            # что на экране прямо сейчас
```

В строках пульса полезны `free` (свободная память), `cpu` (прирост за минуту: ~0,3 с —
норма, десятки секунд — что-то жжёт процессор) и `slide` с `clip` — на чём рамка стоит.
Пульс пишется из фонового таймера, поэтому идущие строки при замершей картинке означают,
что встал UI-поток, а не устройство.

Серия снимков (`./screenshot.sh --series 12`) — единственный надёжный способ поймать то,
что видно глазом лишь мельком: так нашлись и резервные часы, мелькавшие на смене минуты,
и чёрный кадр между слоями. Кадр, выпавший из общего ряда, сразу заметен по размеру файла.
